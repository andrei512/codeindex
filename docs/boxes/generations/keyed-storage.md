# Seeking and replacing index blocks

The candidate layout uses a bulk-loaded copy-on-write B+ tree to find packed blocks by key. A lookup follows one root to the required bytes. A save appends the changed blocks and publishes new roots. This design covers every language. The first experiments exercise Markdown postings and the symbol graph because they expose different causes of expensive edits.

## What the writer must stop doing

The current range map can already reuse physical bytes. However, the graph writer assigns a declaration number by summing all preceding files' declaration counts. Inserting one declaration can change references to declarations in later files. Changing the disk directory cannot eliminate those resolver calls. Stable identities and explicit binding dependencies are part of the storage contract. ## From a root to a byte range

One repository has a current arena, an append-only file. A small selector records the repository, format and writer protocol, generation, arena identity, sealed byte length, checksum, and a fixed set of typed roots. The file catalog, validation dependencies, ID allocators and query products live behind roots. A same-arena child reference carries an absolute offset, encoded length, type, codec and checksum. Begin each publication on a new storage-block boundary beyond the sealed predecessor. Seal children before parents. Child offsets must precede the referring block. A reader checks the expected type, range and arithmetic against its pin's sealed length before decoding. Blocks have independent checksums. Opening a generation does not hash the arena.

An internal page stores ordered separators and child references. A leaf stores ordered keys, an offset directory and inline values or block references. Search selects the last child whose lower fence is at or below the key, then binary-searches the leaf. Range scans keep an ancestor cursor to reach the successor in the same root. A physical pointer from an old leaf to its next sibling could otherwise bypass a replacement. Empty roots have zero rows. Numeric key components compare numerically, strings compare by their exact bytes, and tuples compare component by component. Oversized keys use immutable overflow bytes for full comparison. A digest alone cannot decide equality.

Split by the whole key. For instance, a frequent trigram spans leaves in file-ID order. An edit seeks the pair (trigram, file ID). A common key or a long list of positions must not require rewriting a single unbounded value. Group positions into independently decodable chunks with lower fences. Coalesce a sorted batch of edits before writing each touched leaf, balancing sibling and ancestor. Count unchanged neighbors copied inside dirty pages as part of the write cost.

## What owns each update

- **Source and locations.** A persistent file ID survives a same-path edit. File-owned rows map persistent declaration and use slots to current byte ranges. Keep a slot when old and new declarations match uniquely by the language's owner, scope, kind and descriptor, including overload distinctions. Never recycle a retired slot in the namespace. If continuity is ambiguous, retire the affected identities, allocate fresh ones and invalidate their consumers. Parser ordinals remain local to one analysis. Separate declaration sites from the semantic symbol they denote. An exported symbol can have several declaration sites.
- **Bindings.** Compare two parser projections separately. One holds the language facts consumed by resolution, including exact names, scopes, roles, configuration and coverage. The other holds current positions. Equal semantic inputs and equal site sequence preserve declaration and use slots even when offsets change. On a structural edit retain a use slot only for a uniquely proven origin; withdraw old memberships for unmatched uses. The full-file Rust declaration end belongs to the positions projection. Only language evidence can prove this equivalence. Give the file, context and capability a persistent partition key. Its payload has a replaceable revision. Keep the forward edges and consulted lookup keys for that partition. A lookup records successful and empty scopes, relevant overload membership, search precedence, module/configuration inputs and coverage. A reverse directory identifies partitions that consulted each key. Rebinding replaces old subscriptions as well as old incoming edges. Recompute mutually dependent exports to a fixed point, starting affected cycles from external inputs so a deleted export cannot sustain itself. If a profile cannot prove a complete dependency set, rebind its affected context. Count that cost.
- **Ordered answers.** For name lookup and incoming references, group postings by lookup key and public source path. Each group is itself a seekable paged list of file-local sites in public coordinate and tie-break order. A continuation carries its pinned generation and last complete public ordering key. Use current location rows to display spans. Rekey the groups on a path rename, and reorder a group when relative site order changes. A capped query applies filtering, grouping and deduplication before counting displayed hits and probes for a further eligible hit. A multi-context query merges in public order. Sorting the first 50 internal IDs would select the wrong hits.
- **Search and documents.** Keep the existing product-specific packed payloads where they win on scans. Maintain each file's old contributions so a deletion can withdraw terms, positions and outbound links. BM25 updates chunk counts, total length and document frequency in the same generation. A changed score for an untouched chunk needs no posting rewrite. Markdown locations, ordered headings and qualified links have distinct dependencies. Moving a document can change a relative backlink without changing any written bytes. [Product layouts](../indexes/layout.md)

## Build, edit and publish

A fresh build assigns IDs and merges sorted producer batches under the scheduler's memory budget. Write packed leaves sequentially, then construct parents bottom-up. Count any spill, second pass and temporary bytes. An edit computes old/new contributions once, rebinds changed semantic projections and their subscribers, and appends a batch to the arena. Unchanged roots and child references carry forward. A position shift can touch many rows in one file. A widely used export can legitimately invalidate many files.

For example, appending a comment to a Rust file grows its source-file span. Publish its new source, locations and changed search contributions. If the binding inputs match, reuse its bindings and incoming postings. Adding a previously missing function instead changes scope membership. Follow the stored subscribers of that membership, then withdraw and insert just the changed edges.

The writer holds the refresh lease. It stages the bytes under the selected predecessor, writes and syncs the temporary selector, makes the arena and any new directory entry durable, and rechecks checkout and external evidence immediately before the selector switch. Changed evidence triggers a retry. It atomically replaces the selector and syncs its directory. Ordering follows the existing platform-specific publication guarantees. Before the durable switch, recovery protects both possible roots. On recovery, first reselect and make the visible selector durable. Under the exclusive lease, a writer may truncate an unpublished suffix beyond that root’s sealed length in the active arena. Committed generations within an arena have monotonically increasing sealed lengths. A reader opens the selected arena handle and captures its sealed length under the publication lock, then releases the lock. It uses that handle throughout the query. Unknown required versions fence old writers before cleanup. Use a distinct arena format major and filenames outside legacy cleanup patterns. Migration may require a full build. [Envelope baseline](wire.md)

Compaction bulk-copies reachable blocks into a new arena and rewrites physical references bottom-up while preserving logical IDs. Install it with a new generation only if the selected generation still matches its base. If concurrent updates repeatedly win, compact under the writer lease with measured waiting time. Old readers retain the old arena through their open handles on the supported Unix filesystems. Unlink the old name only after the new selector is durable. A compacted root has no references into its predecessor arena. A failure before selector replacement preserves the predecessor. If replacement succeeds and the directory sync fails, report uncertain publication, retain both possible roots and arenas, and run recovery before reclaiming either. Account for space for both live copies, abandoned tails and open old arenas. Keep compaction off ordinary edits while sufficient disk space remains.

## What would change the choice

Use the current writer as the control. Replay the **same logical updates and queries** against three prototypes. Compare packed copy-on-write pages, a sorted base with a bounded number of immutable edit runs, and SQLite tables keyed by product and logical key with the same packed payloads. SQLite gets sorted bulk insertion, a transaction per generation, prepared statements, and equivalent durable settings. Record schema, journal mode, sync policy, checkpoints and space reclamation. For runs, count tombstones, read-time merging and the foreground merge when the run limit is reached. For pages, count path copying, splits, compaction and old pinned space. SQLite is a benchmark dependency for this comparison.

Replay isolates storage cost. Then run the same cases through the CLI, including parser work, invalidation, publication and reopen. Measure edits that change only locations, add a definition satisfying an earlier miss, shadow an existing target, remove a cyclic export, and rename a file into the first page of a common-name result. Compare every result with a fresh build. Hold a reader across update and compaction, inject failure before and after the selector switch, and verify that an unsupported writer cannot reclaim the new arena.

On the trailing-comment case, require zero unrelated resolutions, current source-file end and correct text search. For the added definition, require the new forward and reverse edges. Move two identical calls by inserting a comment above them and check both new locations with unchanged reverse edges. For a million incoming sites, test one huge file and many small files. Measure bytes and pages for the first 20, a miss, a late continuation and a filter excluding every site. A path rename must change public ordering before truncation. Double unrelated files and compare visited bindings, rewritten pages and bytes. Include broad regex and full posting scans to catch the cost of fragmentation.

Alternate arms on fixed checkouts. Measure empty-to-durable build, save-to-correct-answer, standalone reopen, already-pinned queries, peak memory, physical and logical I/O, maintenance time and space after sustained churn. Release the oldest reader and drain outstanding maintenance before measuring final disk use. Include both the work postponed by a long-lived reader and the worst-case latency when the writer must perform maintenance. Record p50 and p95 per workload. Run the control against itself, then freeze per-workload equivalence margins, minimum sample counts and cache conditions before tuning. Compare public answers across histories; storage IDs may legitimately differ. Run enough samples to estimate each reported percentile, with paired uncertainty intervals. The candidate must improve update latency reproducibly while preserving fresh-build and query performance. A storage replay win alone cannot select the shipping format. Page size, inline threshold, run limit and compaction threshold are experiment parameters. The current format remains the control until the end-to-end gate passes.
