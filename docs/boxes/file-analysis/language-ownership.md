# Language ownership contracts

The language registry selects the analyzer, project resolver, role syntax and navigation profile for a written format. This reference defines their responsibilities and describes the granularity at which the current builder can suspend or reuse work.

## Select a mode at the boundary

A static registry maps a path to a written format or a plain-text fallback. Recognition is product-specific. A role-only or score-only recognition leaves symbol capability unchanged. Each entry names a concrete analyzer, its rules version, navigation capabilities, and its optional project, binding and edit operations. Selection may refine the mode using captured source or observed project configuration. A PHP file can carry a Hack header. A compilation database can select C++ for a written C file. Preserve both identities. Cache local syntax by source identity, effective dialect, the projection of configuration that can change syntax (including preprocessor definitions and forced includes), and extraction version. Binder-only configuration stays out of that key. Path, context, policy and project observations qualify the products that depend on them. Sharing a syntax key does not share two files' symbol identities.

Dispatch once per distinct mode and requested operation. A concrete analyzer may call a statically specialized family walker such as the existing C-family declaration walker. Keep lexical tables and delimiter algorithms shared wherever the rules agree. A language owns any exceptional grammar or binding decision even if one other language currently has the same exception. A separate trait for every token kind would add work without providing another independently selectable operation.

## Four language contracts

The signatures below specify logical inputs and results. Each capability is registered independently. Shared index writers allocate identities, encode rows and publish generations.

1. **`FileAnalyzer`** — `extract(source, mode, requested_products, scratch, output) → Done | Yield | Failed`. Owns lexical boundaries, grammar, local scopes, declaration kinds, use roles, and the evidence needed for later binding. It can emit structural measurements, framework cues and test regions alongside code facts. It lends tokens or paired delimiters to consumers while they live. The scorer owns thresholds, weights and aggregation. For different recovery rules, share tokens and compute the distinct pairing each consumer requires. Capture each requested product's coverage. Parser recovery can yield partial facts with a reason. A fatal failure discards provisional ranges. Resumption, byte ownership and coverage are specified in the [extraction contract](extraction.md).
2. **`ProjectInputs`** — `prepare(unit, written_mode, dependency_view) → contextual selections | Waiting | Failed`. Return one selection per applicable context, each with its effective mode, syntax-input projection and observed revisions. Owns project discovery rules, path precedence, parsing of support files and interpretation of external input receipts. A support file can have no code analyzer. The dependency view supplies captured inputs and records positive and negative observations. Share project preparation by project identity, support revisions and rules version. Conflicting revisions for the same external input in one attempt invalidate the attempt and trigger retry. The scheduler handles readiness and I/O. Formats with no configuration use their written mode and a default context.
3. **`ProjectResolver`** — `bind(analysis, file, context, lookup, output) → sealed partition | Waiting | Failed`. Owns symbol identity rules, lookup precedence, overloads, exports and certainty. Read from relevant units and declared foreign providers through a repository-wide lookup view. An ordered search records misses and membership as well as its chosen target. Emit per-use roles, exact targets or candidates, and coverage. The index derives reverse postings from accepted forward outcomes. File-local bindings can go directly through that same writer. A format with no binding capability publishes its declared coverage. Waiting, binding cycles and closure follow the [resolution contract](../binding/resolution.md).
4. **`EditProof`** — `compare(previous_evidence, current_input, observations, requested_product) → Reuse | ReuseWithLocationPatch | Recompute`. Optional shortcut for a specific product. Its proof covers semantic spelling, local identities, path mapping, relevant dependencies and rule versions. Location patches name a logical local row and its new source span. The storage writer owns physical offsets. Generic identity checks can reuse identical inputs. In the absence of a valid proof, recompute the affected product and compare published observable revisions to determine dependent work. Preserving a call graph leaves source, search postings and score subject to their own checks.

## Role, score and navigation requests

The file analyzer supplies grammar and framework evidence. Its local role operation uses captured bytes and path alone. Its optional contextual role operation asks the project-input provider for observed dependencies from the pinned view, including missing manifests, headers and base types. The role consumer preserves the classifier's label, exact evidence spans and reasons. Context can refine a role query without forcing a project lookup to compute every file's test-score adjustment. If a contextual role is cached, changes to those observations invalidate it.

The scoring engine owns policy, suppressed ranges, thresholds and numeric results. At ordinary thresholds it can read saved measurements. A lower configured threshold may require measurements omitted from the baseline findings. Remeasure affected files from pinned inputs on demand. Preserve the written-language base score and independently select the test adjustment. A guest's test measurements contribute only their specified components, with translated locations and host lines counted once.

A navigation capability describes what a mode can answer. Its coverage describes the evidence available in this context. Keep unsupported operations, partial answers and verified empty answers distinct. A navigation engine label identifies the profile. It alone requests no subprocess.

## Work and ownership

For a definition query, the builder selects the requested products, prepares any syntax-affecting context, and extracts once per distinct syntax key. If several consumers arrive, extend a completed product set only for missing evidence. A single writer owns each product in flight. A binding-only request for a changed dependency uses sealed local evidence from the prior generation. Navigation readers use a pin and read stored outcomes, including their coverage. Independently scheduled text, regex, ranking and Markdown products continue whenever their own prerequisites are ready.

Byte ranges are half-open offsets in the captured source. Worker scratch belongs to one active extraction and can be reused after its final local consumer. Retain private evidence across builds when binding or an enabled edit proof needs it, with a codec identifier and version. Missing optional proof evidence selects recomputation. An unchanged caller can borrow spellings from the pinned source during rebinding. The store validates and frames the payload. The language owner interprets it. Changing semantic rules invalidates dependent facts even when the codec is unchanged. A codec upgrade needs a compatible reader, migration or rebuild before reuse.

A host owns embedded-region discovery, the guest mode and the products requested. Guests borrow their slice and emit local ordinals. The host maps spans, owner IDs and target IDs into host coordinates exactly once. Visibility belongs to the host. For example, HTML can expose a relationship from an inline script while keeping its embedded declaration out of global symbol search. A script source URL introduces a dependency. Script MIME matters. Markdown fences retain searchable text without introducing guest declarations.

## Boundaries the scheduler and query layer can rely on

A new language using an existing prerequisite kind registers a provider and its fixtures. The scheduler operates on product keys, observed revisions, memory charges and ready work. Query rendering operates on stored capabilities, roles and certainty. Neither layer needs a language-name branch to select grammar, determine whether a project change matters, or reinterpret an empty reference list. A genuinely new dependency kind or query meaning requires an explicit shared contract.


## Current scheduling and reuse boundaries

A durable build admits large local jobs against a source-byte allowance. A suspended job holds its source borrow, token prefix, byte cursor, line state and admission charge. Another worker can resume it. The scheduler can make progress on an admitted job even when the remaining credit is zero. A scanner finishes the current lexeme before yielding. Grammar walks finish within their scheduled step. The allowance controls admission and does not predict total process memory.

For a stable file inventory, a compatible snapshot can supply the published forward targets and labels of an unaffected resolver. Each resolver declares the source and support-file changes it observes. JavaScript and Python propagate a source edit through imports, re-exports and possible Python package submodules. A separate import tree retains its answers. Protobuf follows imports and Shell follows sourced files, including transitive inputs. PowerShell checks the imported modules whose export tables its qualified commands can read. C# checks project configuration and the repository-wide presence of a competing source declaration for its modeled framework method. A package manifest edit can still change its public labels. The writer translates old declaration ordinals through the old file boundaries before generating the new reverse postings.

C and C++ record the command set for each translation unit, the include candidates consulted and external SDK receipts. Reordering equivalent compile commands preserves the same contexts. A change to a forced header invalidates its consumers. Two contexts that bind the same written use differently retain separate outgoing and incoming evidence. A checkout whose inventory changes goes through binding with its new path membership. For a Rust source edit, module links and Cargo dependencies define connected groups. A removed module link also invalidates the group containing its former target. A changed Cargo manifest or an edit that changes whether a file yields Rust evidence triggers a Rust-wide rebind.
